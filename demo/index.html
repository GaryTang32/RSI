rsi package · live runs with Claude Haiku

Watching the loop improve an LLM agent, one iteration at a time

Each run below started from an untouched seed and ran through the package's public API (some were cut short by the account's usage cap or a container restart and resumed from their LLM cache). Claude Haiku played both roles: the frozen model the harness calls, and the proposer that rewrites the harness. Every point on a chart is one candidate the model proposed, scored by a locked exact-match grader. The orange and green lines are sealed held-out and out-of-distribution tasks: the loop never saw any of those tasks or their scores, and a write-only monitor scored each new incumbent on them. The proposer's domain description does name the OOD kinds (e.g. "business-day scheduling, chained text transformations"), so OOD measures transfer to unseen tasks of announced kinds. The result line above each chart is a re-score after the run with fresh trials; the chart itself shows in-loop scores and monitor readings, one trial per task.

Reproduce: python experiments/demo/live_demo.py metaharness|rrsi|autoresearch [--suite hard] (recorded runs: python experiments/demo/rescore.py), then python experiments/demo/spend.py && python experiments/demo/plot_demo.py && python experiments/demo/build_page.py. Full per-step traces (prompts, diffs, gate arithmetic) are in demo/runs/<run>/TRACE.md. Small task sets (standard: 12 practice, 8 held-out, 8 OOD; hard: 8, 6, 6) make single runs noisy; treat each chart as one real trajectory, not a benchmark.
