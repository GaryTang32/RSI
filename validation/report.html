Does it match the papers?

Contradicted

  • Dream-RSI "consistently superior at lower compute": never better at equal rounds here; worse on synthetic worlds.
  • Dream-RSI "matches or surpasses" in math: the paper's own Table 1 shows autocorrelation worse.
  • GEPA merge "occurs sparsely": 25-69 merge attempts per run under the reference cap.
  • Meta-Harness "code search regularises towards coherent algorithms": a live run put a template-specific regex solver on the frontier.
  • Overview: EvoMap "looks locally, then asks the hub" (Evolver asks the hub first); autoresearch "can't change how it is graded" (the upstream lock is only an instruction); Dream-RSI code "open" (not released).

New mismatches found (open)

  • Dream-RSI: a policy can keep module-level state across replay episodes and so peek (affects the Pareto objective and beta sweep, not Eq.1).
  • Dream-RSI: the Listing-2 developer prompt is a condensed paraphrase missing about 20 rules.
  • GEPA: the hard merge cap limits accepted merges, not invocations.
  • RRSI: the leakage denylist includes practice-set answers (an oracle the reference lacks); the proposer sees the noise band and cost weights.
  • Meta-Harness: the context-cost objective counts only the last call and can be gamed.
  • SoL-Pi, EvoMap, autoresearch: a dozen small port and measurement differences, listed per method.

Behaviour vs the paper

  • Meta-Harness matches the paper here. The proposer diagnosed failures from raw traces: both live runs quote concrete trace lines, and the candidates target those diagnoses. Every valid candidate was evaluated on the search split only. The frontier trades accuracy against context: the offline best has 3.1x less context than fewsho
  • Meta-Harness does not match the paper's claim that code-space search regularizes toward coherent algorithms (§3, §5). Live r2 produced a template-regex solver at cost 0 that sits on the Pareto front, and a docstring containing a search instance with its answer. The main loop has no guard against this (spec A8.2).
  • Meta-Harness selection on the search set did not track generalization. Offline, the last two incumbent changes gained 1 and 3 search examples while sealed ood fell from 0.654 to 0.558. In live r2, _best gained on search and holdout but 0 on ood. This is consistent with spec A8.3/A8.4 (small transfer, no noise band).
  • Meta-Harness improvement rate: 6 of 12 offline candidates, and 2 of 6 per live run, became incumbents, against the reported <5 in 100 useful edits. This comes from weak seeds and search sets of 10-144 examples, not from the method.
  • Meta-Harness live outcome variance: two runs with identical configs ended at ood 1.0 and 0.25 (N=3, trials=1, n=6/4 sealed tasks). A single live run is anecdotal.

Apply it to a new problem

Write a Domain (tasks with sealed holdout/ood splits and a locked grader), measure noise on the seed, pick a method, run, then read the transfer report and the trace. The Claude Code skill .claude/skills/rsi-improve walks through it.

python -m rsi.cli recommend --prompts-only
python -m rsi.cli improve --method rrsi --problem my_problem.py:make --llm claude:haiku --out runs/x --set T=6
python -m rsi.cli inspect runs/x      # TRACE.md: prompts, diffs, gate arithmetic, shadow held-out scores

Limits: CPU-scale analogues of the papers' GPU and frontier-model benchmarks; the RRSI and SoL-Pi paper texts were not retrievable, so those specs rest on the released code and secondary sources. Simulated-domain numbers show mechanisms, not benchmark results.
