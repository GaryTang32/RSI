# RRSI: claim-by-claim audit

This page checks our implementation (`rsi/rrsi/`, `rsi/domains/harnessworld/`) against **every** claim attributed to "RRSI: Regularized Recursive Self-Improvement of Agent Harnesses" (Xia et al., arXiv 2609.24972) in our spec and in the user's overview. It covers mechanisms, table numbers, qualitative findings and caveats.

**Status (2026-09-25, after the fixes).** The audit first ran on unchanged code. Every mismatch it found (§3, N1–N9) and every open item of the validation register was then reproduced and fixed, or given a disposition; §5 ("Fix log") records each one. The claim rows, the counts in §1 and the evidence columns below have been **updated to the post-fix reruns**: all loop experiments (E1–E7, E9, E11–E13) were rerun at full settings on the fixed code, and both offline validation runs were regenerated. The prompt fixes reseed the scripted mocks, so the numbers are a new realization; where a verdict moved, the row says so.

**Sources used.**
- Our verified spec, `docs/methods/rrsi.md` (§§2–8), and the user's overview, `scratchpad/doc.txt` (the RRSI section plus the side-by-side and "lessons" sections).
- The reference code, `google-research/rrsi@be50316`, in `scratchpad/src/google-research__rrsi`.
- Secondary paper sources, in `scratchpad/papers/rrsi_secondary/`. **The paper PDF could not be retrieved**, so every "paper" claim below comes to us through the code README, the overview or a secondary read-through (the spec tags each one).
- Our evidence:
  - `docs/methods/rrsi-impl.md`;
  - `results/rrsi/*.json`, experiments E0–E13;
  - `validation/rrsi/{AUDIT,RUNS}.md` and the run directories.

**New checks run for this audit.** All were offline, took under 4 min of CPU in total, and made no LLM calls. The scripts are in `scratchpad/claims_rrsi/` (outside the repo).
- `diff_test.py` (12 s) is a randomized differential test of our pure functions against the reference code, which it imports directly. It covers:
  - Algorithm 2 (`select_round`), 6,000 random rounds over the default, coding, workspace and eng presets;
  - `edit_budget`, every (T ≤ 59, b_min ≤ 3, b_max ≤ 6, t) combination;
  - `stall_flag`, 3,000 cases;
  - the `History` summaries (T_t, g_t, B_t, accepted counts, render), 300 random ledgers;
  - `normalize`, `classify_diff` and `novelty`, 3,000 synthetic diffs;
  - `aggregate`, 500 weighted cases;
  - `calibrate`: repeated evaluations exactly, and the bootstrap within Monte-Carlo error.
- `boot_conv.py` repeats the bootstrap comparison at 20,000 resamples.
- `policy_swap.py` (3 min) is a HarnessWorld analogue of paper Tables 3–4, run for 50 seeds × {full, unregularized} × {STRONG, WEAK} search policy. It evaluates each final harness under a still weaker policy (VWEAK, strength −2) that was never used in any search. Its STRONG rows reproduce E1's stored numbers exactly, a determinism check.
- A re-analysis of the stored E1 and E2 rows (`results/rrsi/e1_overfitting.json`, `e2_ablations.json`):
  - per-seed held-out regressions;
  - harness size, which gives a steps proxy, since HarnessWorld steps = 1 + active mechanisms (`rsi/domains/harnessworld/domain.py:114`);
  - token ratios.
- `tests/test_rrsi_*.py`: 62 passed in 14 s (before the fixes). After the fixes, 77 passed, including the 15 regression tests in `tests/test_rrsi_fidelity.py` and `test_rrsi_generic.py`.

**Post-fix checks** (scripts in `scratchpad/fix_rrsi/`):
- `diff_test.py` rerun: 0/6,000 Algorithm 2 mismatches (was 18 admissibility / 15 winner), 0/300 render mismatches (was 23), 0/3,000 `normalize` mismatches (was 20).
- `repro_*.py`: every finding reproduced on the pre-fix code before its fix.
- `n3_hw_equiv.py`: the precheck verdict on all 5,400 catalog mechanisms of 50 HarnessWorld worlds, with and without the answer key.
- `live_critic_check.py`: the Haiku critic on the recorded live leak, fresh cache, $0.025.
- `policy_swap.py`: the auditor's check, rerun on the fixed code (its STRONG rows reproduce the new E1 exactly).

**Mechanisms.** Our pure mechanism functions now agree with the reference code exactly. The differential test finds 0 mismatches in:
- Algorithm 2: 0/6,000 random rounds (18 differed before the tie fix, F1);
- `render`: 0/300 (the BASELINE row, F5);
- `normalize`: 0/3,000 (the `tool` alias, F6);
- `edit_budget`, `stall_flag`, T_t, g_t, B_t, ν, `aggregate` and the repeated-evaluation δ.

The bootstrap δ equals the reference's within Monte-Carlo error (≤ 0.6% relative at 20,000 resamples).

What the fixes changed:
- The proposer now sees only the reference's context: no δ, S*, S_t or T, and symbolic β/w (F2).
- The precheck denies task ids and patterns, not answers (F3).
- A missing trial carries its task's weight (F4).
- The smoke runs the code's 2 or 4 tasks (F9).
- A resumed run's USD budget counts the killed process's spend (F10).
- "The eval_invalid retry re-measures the whole job" (N7) was an invalid finding: the retry already re-runs only the missing trials (F7).

The 5 PARTIAL mechanisms are documented plumbing substitutions or inferred definitions, not defects:
- the single-shot proposer and digesters instead of the 40-turn JSON agent (M4, M28);
- a b_t that ends at 2, following the code rather than the paper's "ends at one" (M9);
- the ablation groups and the unregularized baseline, which are inferred, not taken from the paper (M34, M35).

Replacing git with the artifact store (M3) changes no decision, so M3 counts as REPRODUCED.

**Quantitative.** Every table number in the paper (Terminal-Bench 2.1, SWE-bench Verified, Harvey LAB, JobBench, GDPval, APEX-Agents, EngDesign, Frontier-Eng, the Gemini rows, 2.42M tokens and 26.3 steps) is **NOT TESTABLE HERE**. Each one needs frontier LLM policies (Claude Opus 4.8, Gemini 3.5 Flash and 3.1 Flash Lite), the real benchmarks with their graders, and many thousands of agent trials. Our CPU runs test only **directional analogues**, and those are scored under the qualitative claims. We make no claim about the absolute numbers.

**Qualitative (post-fix reruns).** The core story still reproduces in the synthetic HarnessWorld:
- unregularized evolution overfits: highest practised score, lowest unseen score, 71× H_0's tokens vs 3.5× for full RRSI;
- RRSI practises less, transfers better (paired OOD +20.2 [+17.3, +23.3]) and is cheaper;
- no seed of full RRSI regressed on any unseen split (0/50);
- the harness transfers to weaker policies never used in the search (E12, policy swap);
- the same verdicts hold with the three-lens LLM analyst in place of the heuristic (E1 robustness arm, F8).

Three claims are NOT REPRODUCED:
- "removing the proposal guards raises the practised score and lowers OOD" (L4): in the post-fix realization −proposal is indistinguishable from full RRSI on every metric. It was borderline in earlier realizations.
- "a weaker search policy gains more on the evolve set", an implication of Table 3/4 (L12): the policy swap now shows the opposite, −4.2 [−6.6, −1.7].
- "δ at z = 2 clears an unchanged harness ~97.5% of the time" with the code's estimator at k = 2 (M37; 91.6%). This is an overclaim in the reference's own docstring.

"Rejected ideas stay rejected" (L19, E8) was never run: it needs a live LLM proposer over many rounds, so it is NOT TESTABLE HERE.

Magnitudes are not calibrated: unregularized tokens are 71× H_0 here against 2.4× in the paper.

**Live (fixed code, $0.93, one sample).** Haiku's LLM review caught the answer leak recorded in the pre-fix live run on its own. But it passed practice-family regex routers, one of which quotes an evolve question. The run gained on evolve and held-out (0.33 → 1.00, 0.42 → 0.83), not on OOD (0.46 → 0.46). This is the critic-is-not-a-guarantee caveat (C8), observed live.

**Caveats.** Most of the paper's and the spec's caveats show up in our runs:
- results depend on the realization;
- the critic misses obfuscated leaks, and live it missed practice-family routing;
- the gap between evolve and OOD gains narrows but does not close;
- the winner's curse inflates S*;
- the budget never reaches b_min;
- B_t lists components with no machinery to prune.

One caveat-row is CONTRADICTED: C7, the third-party hypothesis that the annealed budget alone explains most of the OOD gain. It is not a paper claim. In E2b, budget-only gives OOD −1.2 while selector-only gives +17.0.

"Every evolved harness costs more than H_0" (C20) holds on HarnessWorld and in the regenerated AgentQA run (1.76×). The stage-B AgentQA realization was a counter-example (626 vs 736 tokens per trial). It stays NOT TESTABLE HERE for the paper's domains.

**Live spend of the fix stage: $0.951**, all Haiku through `claude -p` with fresh caches:
- $0.025: one critic call on the recorded leak;
- $0.688: live smoke, first attempt, stopped by its 900 s wall after round 0;
- $0.238: live smoke, round 1, with round 0 replayed from the cache at $0.

## 3. Mismatches the earlier reviews missed

The impl notes (§5), two adversarial reviews (impl §6.1–6.2) and the stage-B audit already list the documented deviations: the proposer protocol, the digesters, no git, the added-line precheck, path-glob taxonomies, `trust_code_tags`, the resume counts for ν, the switch-aware constitution and the shadow monitor. The items below are **not** flagged as deviations from the reference anywhere in `docs/methods/rrsi-impl.md` or `validation/rrsi/AUDIT.md`. They were found by the side-by-side reading and the differential test for this audit.

- **N1: Algorithm 2 tie semantics differ.** *Status: **fixed** (§5, F1): raw float comparisons, as in the code; `Config.tie_eps` is the opt-in tolerance. The differential test now finds 0/6,000 mismatches.*
  - Ours: `CostRule`/`NoiseFloor` use `dS > δ + 1e-9`, `S' ≥ floor − 1e-9` and `shaped > 1e-9` (`core/gates.py:151,177,184`).
  - Ref: raw `delta_S > delta`, `S' < floor` and `shaped > 0` (ref `rrsi/selection.py:84-91,107-108`).
  - When dS equals δ exactly in exact arithmetic, the ref's branch depends on float rounding: 0.55 − 0.50 = 0.05000000000000004 > 0.05 takes the cost-rule branch, while ours takes the within-band shaped rule.
  - Impact: 18/6,000 random rounds changed admissibility (15 winners), all at exact ties. This matters only when δ is an exact multiple of the score quantum. That is unlikely with a calibrated δ, but possible with a hand-set δ (e.g. δ = 0.05 on 20 tasks at k = 1).
  - Ours is the mathematically consistent reading. Impl §5.17 mentions `TIE_EPS` only for the ablation gates.
- **N2: the proposer sees numeric thresholds the reference proposer never sees.** *Status: **fixed** (§5, F2); `Config.proposer_numbers` is the opt-in.*
  - `round_directives` (`loop.py:420-424`) carries δ, S*, S_incumbent, T and the trace ids.
  - `default_constitution` fills in β0, β1, w_s, w_c and w_n (`constitution.py:172`).
  - The ref's SKILL.md states the rules symbolically ("beta0 + beta1 x (gain)"), and its context has no δ or S* (ref `rrsi/propose.py:257-302`).
  - The mocks ignore the text, so the offline results are unaffected. With a live LLM this could let the proposer aim for gains just above δ, the "adaptive poisoning" concern (C9).
- **N3: the leakage precheck is an oracle.** *Status: **fixed** (§5, F3); `Config.precheck_answers` is the opt-in. Correction to the impact stated below: on HarnessWorld the answer key never changed a precheck verdict, because every literal HarnessWorld leak is keyed by evolve task ids, which the code's precheck also denies (600/600 catalog leaks over 50 worlds, either way). The oracle mattered for AgentQA (answers keyed by question text) and for answer-only leaks.*
  - `Domain.leakage_terms` returns every evolve task id **and every target answer of 3 or more characters** (`core/domain.py:166-175`), and `RRSICritic` puts them in its denylist (`critic.py:112-117`).
  - The ref's prechecks hold task names (coding), id patterns (workspace, eng) and grader artefacts; answers and entities are left to the LLM review.
  - As a result, in HW, literal answer-table leaks are caught deterministically, and the E3 "catch 0" arm is regex-only in name only. This flatters the critic in E1, E3 and E12 compared with the paper's setting.
  - Impl §5.4 lists "answers" as a feature, but no verdict discusses the advantage. A faithful arm would restrict the denylist to ids and patterns.
- **N4: missing trials are padded with weight 1.0.** *Status: **fixed** (§5, F4).* `from_core` pads with weight 1.0 (`evaluate.py:175-179`), whereas the ref's workspace adapter gives a missing trial the task's criteria count. This affects only weighted (Harvey-style) domains; no experiment uses weights.
- **N5: `History.render` drops the BASELINE record** *(status: **fixed**, §5, F5; 0/300 mismatches)* (`history.py:163`). The ref renders it, and it counts toward the ≤ 4 unmeasured rows. Cosmetic: in 23/300 random ledgers, this row is the only difference.
- **N6: the `tool` alias.** *Status: **fixed** (§5, F6); `Config.component_aliases` is the opt-in. 0/3,000 mismatches.* Ours canonicalises a declared `tool` to `client_tool` (`components.py:49,161-165`). The ref treats `tool` as outside K, bounces it in done(), and re-tags it from the diff. This gave 20/3,000 `normalize` differences. It is an extension and harmless for tagging, but a live proposer is not bounced for a vocabulary slip the ref would bounce.
- **N7: the eval_invalid retry measures the whole job again with the same job seeds** *(status: **invalid finding**, §5, F7: the core `Evaluator` keeps every graded trial of the run in memory, so the retry already re-runs only the missing trials, as the code's resume-safe runner does. Reproduced: 40 slots with 19 infrastructure failures → 59 executions, not 80. A test now pins this.)* (`loop.py:151-157`, `evaluate.py:192-195`). The ref's retry refills only the missing trials of a resume-safe run. In a deterministic domain our retry is a no-op. With a live task model it re-pays for every trial.
- **N8: every E-experiment used the heuristic analyst, not the three-lens LLM analyst.** *Status: **documented and checked** (§5, F8): each row records `analyst_mode`, and E1 now has an LLM-analyst arm, served by the HarnessWorld mocks, whose verdicts match.* `Config.analyst="auto"` needs an explicit `llm_analyst` (`loop.py:90-91`), and `_common.run_hw`/`run_aq` pass only `llm_propose`. F_t in E1–E12 is therefore a deterministic clusterer over grader feedback. The LLM digesters and aggregator appear only in the validation runs. Impl §5.3 calls the heuristic "the offline default", but no E-row says it applies to all of them.
- **N9: the smoke check is generic** *(status: **fixed**, §5, F9)* (`core/domain.py:177-184`): 1 task, seed 0, error-only. The ref's per-domain smoke checks need 2–4 tasks, and eng also requires no-payload = 0 and combined_score > 0. A candidate that runs but produces empty payloads would pass our smoke check and fail the ref's. That affects cost (an evaluation is spent on it), not selection.
- **Re-confirmed, already known:**
  - the budget never reaches b_min;
  - the E10 bootstrap under-covers at k = 2;
  - the AQ parts of E1b, E12 and E13 were **not** re-run after the stage-B mock and analyst fixes (AUDIT §5), so the AQ numbers quoted in L2 and L11 came from pre-fix code. *Status: **rerun** (§5, F14); L2 and L11 now quote the new numbers.*

## 4. What would be needed to fully reproduce

1. **Frontier policies and the real benchmarks.** Q1–Q27 need:
   - Claude Opus 4.8 as policy, proposer, analyst and critic, plus Gemini 3.5 Flash and 3.1 Flash Lite;
   - Terminal-Bench 2.1 (89 tasks, Docker via harbor) and SWE-bench Verified (500);
   - Harvey LAB pinned at `1da4750`, with the Gemini-3.5-Flash rubric judge;
   - JobBench, GDPval and APEX-Agents through the archipelago runner;
   - EngDesign-Open (61 tasks), EngDesign v1 hardened and Frontier-Eng with their simulators and the (unpublished) medal computation.

   At the paper's settings a run costs m·|D|·k = 356–488 agent trials per round for T = 20–40 rounds per domain, plus baselines and 3 ablation arms. Our package would also need adapters (`Domain` subclasses) for each benchmark.
2. **The baselines.** Meta-Harness, AHE, TTHE and HarnessX all need to run under the same budget and on the same start harness (Table 1, Q10–Q14, L6, L31). `rsi/metaharness` exists but has never been run on an RRSI domain. AHE, TTHE and HarnessX are not implemented.
3. **Faithful proposer and analyst plumbing.** The ref's 40-turn JSON action agent (list/read/edit/write, read_trace over all traces) and the tool-using digesters (`digest_many`, grep/read/bash allowlist) are needed to test the proposal-side claims (L4, L19/E8, L20) with a real LLM; the shallow mocks cannot "refine what has credit". N2 (numeric δ and S* in the proposer's context) and N3 (the answer-key denylist) are now fixed (§5 F2, F3), so the critic's precheck and the proposer's context are on the paper's footing; the agentic plumbing is not.
4. **The paper's exact definitions.**
   - the unregularized loop's keep rule (M35);
   - which mechanisms belong to each Table 2 ablation group (M34);
   - whether the paper's b_t reaches 1 (M9).

   All three need the paper text, which the egress proxy blocked.
5. **Statistics the paper omits.** To measure the noise itself:
   - repeated runs (≥ 3 seeds per arm on real benchmarks), so the Table 1/2 differences (0.2–4 pts) can be compared with run-to-run noise;
   - a re-measured incumbent, or a held-out-validated S*, to separate the method from the winner's curse (C11);
   - a δ estimator that covers at k = 2 (E10's √(k/(k−1)) correction, or R ≥ 5 repeats).
6. **Calibration of the synthetic world.** HarnessWorld magnitudes (71× tokens unregularized vs 2.4× in the paper, unregularized OOD −2.8 vs +0.6; 93× and −3.4 in the pre-fix realization) come from world assumptions (`context_penalty`, the leak and narrow-mechanism shares). Before any magnitude comparison, HW would need fitting to at least one real run's per-mechanism effects and costs.
